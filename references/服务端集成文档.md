# 服务端集成文档

版本：v1  

适用范围：游戏服务端接收发货通知，以及向发行方上报通用事件。

## 测试环境

测试环境域名：`https://openapiv3.qk6.top`

本文中的发行方接口地址均由该域名与接口路径组成。游戏方提供的发货通知地址不受此域名限制。 

## 1.发货通知

玩家支付成功后，发行方支付服务会向游戏方提供的 `notify_url` 发起 HTTP POST 请求。游戏方验签通过并完成幂等发货后，必须按约定响应。

### 1.1 对接配置

| 配置项 | 说明 | 提供方 |
|-|-|-|
| `notify_url` | 游戏方接收通知的 HTTPS 地址，例如 `https://game.example.com/pay/notify` | 游戏方 |
| `app_secret` | 发货通知签名密钥 | 发行方 |

### 1.2 请求协议

- 请求方法：`POST`
- 内容类型：`application/json`
- 超时时间：10 秒；超时或响应不符合要求时，本次通知视为失败

请求 Header：

| Header | 类型 | 说明 |
|-|-|-|
| `content-type` | string | 固定为 `application/json` |
| `x-timestamp` | number(string) | 发行方服务器当前 Unix 秒时间戳，例如 `1756123456` |
| `x-nonce` | string | 16 位小写十六进制随机串，用于防重放和成功应答回显 |
| `x-signature` | string | SHA-1 小写十六进制签名，共 40 位，**签名算法见：发货通知签名算法** |

请求 Body：

| 字段 | 类型 | 必填 | 说明 |
|-|-|-|-|
| `order_no` | string | 是 | 发行方平台订单号，全局唯一 |
| `game_order_id` | string | 是 | 游戏方订单号 |
| `amount` | number | 是 | 实付金额，整数，单位为币种最小单位；CNY、USD 均为分 |
| `attach` | string | 是 | 下单时透传的数据，原样返回；无内容时传空字符串 |
| `paid_at` | string | 是 | 支付完成时间 |

请求示例：

```HTTP
POST /pay/notify HTTP/1.1
Host: game.example.com
Content-Type: application/json
x-timestamp: 1756123456
x-nonce: a1b2c3d4e5f60718
x-signature: SIGNATURE

{
  "order_no": "260907120001A1B2C3D4E5",
  "game_order_id": "GAME20260907120000123",
  "amount": 600,
  "attach": "{\"server\":1001}",
  "paid_at": "2026-08-28T14:40:34+08:00"
}
```

### 1.3 成功应答

游戏方完成验签及发货后，返回 HTTP 200，并在响应体中原样回显请求 Header 的 `x-nonce`：

```HTTP
HTTP/1.1 200 OK
Content-Type: text/plain

a1b2c3d4e5f60718
```

响应体只能包含 nonce 裸字符串，不能添加引号、JSON 包装、换行或空格。只有 HTTP 200 被识别为成功，201、204 等其他状态码均视为失败。

## 2.发货通知签名算法

发货通知使用 SHA-1 签名。游戏方收到通知后，必须验签通过才能执行发货。

### 2.1 参与签名的字段

| 来源 | 字段 |
|-|-|
| 请求 Body | `order_no`、`game_order_id` |
| 请求 Header | `x-nonce`、`x-timestamp` |
| 服务端配置 | `app_secret` |

签名使用 Body 中的 `order_no`、`game_order_id`，但不对完整 Body JSON 原文签名。

### 2.2 签名算法

1. 将 `order_no`、`game_order_id`、`app_secret`、`x-nonce`、`x-timestamp` 转换为字符串。
2. 将五个字符串按字典序升序排序。
3. 使用下划线 `_` 连接排序后的字符串。
4. 对连接结果计算 SHA-1，输出 40 位小写十六进制字符串。
5. 签名不添加任何前缀。

```Plain Text
plain = [body.order_no, body.game_order_id, app_secret, header.x-nonce, header.x-timestamp]
  .map(String)
  .sort()
  .join("_")

x-signature = sha1(plain)
```

### 2.3 Node.js 验签示例

```JavaScript
import { createHash, timingSafeEqual } from "node:crypto"
export function verifyDeliveryNotify(headers, body, appSecret) {
  const ts = String(headers["x-timestamp"] || "")
  const nonce = String(headers["x-nonce"] || "")
  const actual = String(headers["x-signature"] || "")
  const orderNo = String(body?.order_no || "")
  const gameOrderId = String(body?.game_order_id || "")

  if (!/^\d+$$/.test(ts)) return false
  if (!/^[0-9a-f]{16}$$/.test(nonce)) return false
  if (!/^[0-9a-f]{40}$/.test(actual)) return false
  if (!orderNo || !gameOrderId || !appSecret) return false

  const plain = [orderNo, gameOrderId, appSecret, nonce, ts]
    .sort()
    .join("_")
  const expected = createHash("sha1").update(plain).digest("hex")

  return timingSafeEqual(
    Buffer.from(actual, "hex"),
    Buffer.from(expected, "hex"),
  )
}
```

```Plain Text

验签方计算出的结果与请求 Header 中的 `x-signature` 完全一致时，验签通过。
> `app_secret` 只允许保存在可信服务端，不应下发到网页、小程序或其他客户端。
```

# 开放服务

本文面向开放服务调用方

## 1. 接口请求约定

 `POST` 接口，请求体格式为 `application/json`。

请求时必须携带以下 Header：

| Header | 类型 | 说明 |
|-|-|-|
| `x-app-id` | string | 平台分配的应用 ID |
| `x-timestamp` | string | Unix 秒级时间戳 |
| `x-nonce` | string | 8 字节随机数编码成的 16 位小写十六进制字符串 |
| `x-signature` | string | 40 位 SHA-1 小写十六进制签名，**参考：签名算法** |

## 2. 通用事件上报（可选）

描述：除 SDK 默认上报的事件外，任何需要同步给平台的其他事件数据，均可通过该接口进行上报。

### 请求 Body

| 字段 | 类型 | 必填 | 说明 |
|-|-|-|-|
| `event` | string | 是 | 事件名称 |
| `ext` | object | 是 | 事件数据，可包含任意字符串键及 JSON 值 |

### 请求示例

```Bash
curl -X POST 'https://openapiv3.qk6.top/report/event' \
  -H 'Content-Type: application/json' \
  -H 'x-app-id: 100019' \
  -H 'x-timestamp: 1756123456' \
  -H 'x-nonce: a1b2c3d4e5f60718' \
  -H 'x-signature: SIGNATURE' \
  --data-raw '{
    "event": "login",
    "ext": {"event":"login","ext":{"areaId":"1","areaName":"1区","openId":"3a4800531db1eb84c1bb7f8e7fdb67ea","roleId":"45940775","roleName":"S710.桑炎彬","roleLevel":80,"professionId":"1","professionName":"战士","timestamp":1790159595,"vipGrade":5,"loginTime":1700000000000,"offlineTime":0,"money":123400,"loginIp":"172.16.0.46","roleTurnup":1,"familyId":"F1001","familyName":"凌霄阁"}}
  }'
```

### 成功响应

```JSON
{
  "code": 0,
  "message": "ok",
  "data": true
}
```

## 封解禁（必接）

### 请求地址

游戏方提供url地址

### 请求 Body

| 字段 | 类型 | 是否必填 | 说明 |
|-|-|-|-|
| `type` | string | 是 | 操作类型，见下表 |
| `server_id` | string | 否 | **区服 ID** |
| `open_id` | string | 条件 | 用户唯一标识，只传`open_id`，那么控制这个账号下的所有角色 |
| `role_id` | string | 否 | 角色id ，只传`role_id`，那么控制这个角色 |
| `role_name` | string | 否 | 角色名，只传`role_name`，那么控制这个角色 |
| `ip` | string | 否 | ip，只传ip，那么控制这个IP下的所有玩家 |

| `extension` | string | 否 | 渠道扩展字段，游戏服务端可忽略 |

`type` 取值：

| `type` | 含义 |
|-|-|
| `lock` | 禁言 |
| `unLock` | 解禁言 |
| `close` | 封号 |
| `unClose` | 解封号 |

# 签名算法

把参与签名的值转成字符串 → 过滤空值 → 按字典序升序排序 → 用下划线 `_` 连接 → 计算 SHA-1 → 输出 **40 位小写十六进制**，不添加任何前缀。

### 参与签名的字段

| 方向 | 参与签名的字段 |
|-|-|
| 入站：游戏方 → 平台 | `app_secret`、`x-app-id`、`x-timestamp`、`x-nonce`（**Body 不参与**） |
| 出站：平台 → 游戏方（发货通知） | 上述四个值 + **Body 中约定的业务字段**（见 2.1） |
| 出站：平台 → 游戏方（角色查询 / 区服查询 / 封解禁） | 上述四个值 + **Body 顶层的所有非空值** |

区别只在**出站时 Body 的哪些值要一起进签名**。

### 计算步骤

1. 生成 8 字节随机数，并编码成 16 位小写十六进制 nonce。
2. 将参与签名的值（见上表）逐个转换为字符串。
3. 过滤掉空值（`null`、`undefined`、空字符串）。
4. 将所有字符串按字典序升序排序，使用下划线 `_` 连接。
5. 对连接结果计算 SHA-1，输出 40 位小写十六进制字符串。

```Plain Text
plain = [参与签名的值...].filter(非空).map(String).sort().join("_")
x-signature = sha1(plain)
```

### 入站：游戏方 → 平台

`开放服务`等接口使用本规则 —— **只签 Header 的四个值，请求 Body 不参与签名**。

Node.js 生成请求头：

```JavaScript
import { createHash, randomBytes } from "node:crypto"
export function createOpenSignHeaders(appId, appSecret) {
  const timestamp = String(Math.floor(Date.now() / 1000))
  const nonce = randomBytes(8).toString("hex")
  const plain = [appSecret, String(appId), timestamp, nonce]
    .sort()
    .join("_")

  return {
    "x-app-id": String(appId),
    "x-timestamp": timestamp,
    "x-nonce": nonce,
    "x-signature": createHash("sha1").update(plain).digest("hex"),
  }
}
```

### 出站：平台 → 游戏方

`渠道服务`等接口使用本规则 —— **签 Header 的四个值，请求 Body 参与签名**。

取值的约定：  
1. **空值口径**：只有 `null`、`undefined`、`空字符串`不参与签名；`0` 与 `false` 要参与。

2.**嵌套值取 JSON 文本**：值是对象 / 数组时，取它的 `JSON.stringify` 结果整体作为一个值参与签名（`{k:"v"}` → `{"k":"v"}`，`[1,2]` → `[1,2]`），**不展开成多个值**。验签方按收到的报文 `JSON.parse` 后原样 `JSON.stringify` 即可复现 —— 所以游戏方**不要重排或改写 Body 内嵌套结构的字段顺序与格式**。

Node.js示例

```JavaScript
import { createHash } from "node:crypto"

export function verifyOpenRequest(headers, body, appSecret) {
  const bodyValues = Object.values(body ?? {})
    .filter((v) => v !== undefined && v !== null && v !== "")
    .map((v) => (typeof v === "object" ? JSON.stringify(v) : String(v)))

  const plain = [
    ...bodyValues,
    appSecret,
    headers["x-app-id"],
    headers["x-timestamp"],
    headers["x-nonce"],
  ].sort().join("_")

  const expected = createHash("sha1").update(plain).digest("hex")

  return expected === headers["x-signature"]
}
```

```Plain Text

> 验签方计算出的结果与请求头中的 `x-signature` 完全一致时，验签通过。
```
